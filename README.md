# 台灣人代表

> 要動這個 repo 的話，先讀 [AGENTS.md](AGENTS.md)。

22 個縣市代表角色的展示站。單一 `index.html`，沒有建置步驟、沒有相依套件，
用瀏覽器直接開或丟任何靜態主機都能跑。

## 這個名字的意思

「代表」有兩種讀法，這個系列兩種都要。

**名詞的讀法**：一個角色，站出來代表這個地方。
**動詞的讀法**：這個地方的人，代表了某一種生活態度。

所以「台灣人代表」不只是「一個代表台灣人的角色」，
也是「台灣人代表了多元包容、創新進步、人情純樸、團結勇敢」。

同理，「高雄人代表」講的不是高雄人長什麼樣子，
而是高雄人代表了哪一種生活態度。市花、市樹、市鳥那些當然可以寫，
但它們是註腳，不是主詞。

台灣，不只是地理上的位置，更是一種生活的態度。

## 為什麼 22 張都是同一個角色

這是刻意的。角色固定，變的是她走到哪裡、身上帶著什麼。

換成 22 張不同的臉，等於宣稱「這就是某地人長的樣子」，
那是拿一張臉去代表幾十萬人。固定角色把命題換掉：不是「她是高雄人」，
而是「她在高雄」。地方性交給背景、穿搭與配件去承載——
沒有人會為了一朵木棉花吵架，但會為了一張臉吵。

## 改內容

**`data/counties.json` 是唯一的事實來源**，不要直接改 `index.html` 裡的常數——
那些是由腳本產生的，手改會在下次同步時被蓋掉。

一個縣市一筆，主要欄位：

| 欄位 | 意思 |
|---|---|
| `name` / `en` / `id` | 中文名、英文名、圖檔 slug |
| `poster` | 對應的原始海報檔名（22 縣市共用 20 張，見下） |
| `base` | 底圖檔名，`register_base.py` 寫入 |
| `symbols` | 市花／市樹／市鳥，各自帶 `source` 標可信度 |
| `places` / `foods` / `traits` | 卡片上那三欄 |
| （無欄位）「一起住」 | 新住民人數，不在 counties.json，由 `data/newcomers.json` 帶進來 |
| `quote` | 卡片下方的短句 |
| `scene.landmarks` / `landmarks_en` | 背景地標，英文是給模型看的外觀描述 |
| `scene.plants` / `plants_desc` | 前景植物，描述寫到瓣數與花序 |
| `scene.hand` / `hand_zh` | 手上拿的東西 |
| `scene.outfit` / `hair` | 服裝與髮飾，**讀自原海報**不是自己發明 |
| `scene.accessory_basis` | 非花配件的依據，對不回資料的配件一律拿掉 |
| `scene.right_zone` | 右側留白畫海還是天空遠山（內陸縣市畫海是事實錯誤） |
| `scene.flower_shown` | **實際畫在頭上的花**。多數等於 symbols.flower，台南是鳳凰花（市樹） |
| `scene.hair_zh` / `outfit_zh` | 髮飾與服裝的中文說明，給人看的 |
| `scene.hair_basis` | 髮飾對應到哪一筆查證資料 |
| `quote_basis` | 那句引句取自海報的哪個位置、改了什麼 |
| `symbols.flower/tree/bird` | 各帶 `value`／`source`／`url`／`note` |
| `verified` / `notes` / `todo` | 查證紀錄、注意事項、待辦 |
| `group` / `tagline` / `share` | 行政層級、原海報標語、分享圖用的欄位 |

改完要跑 `tools/sync_split.py` 同步進 `index.html`。

**一個縣市可以有多張。** 同一個陣列裡，沒有 `culture` 欄的是**普通版**（「阿蕊在這個地方」，
一律當代穿著），有 `culture` 的是**特別版**（「阿蕊穿某族的服飾」），靠 `name` 區分：
`台東縣` 與 `台東縣・卑南族`。特別版只寫要覆寫的欄位，其餘繼承所屬縣市。

```bash
python3 tools/build_prompt.py 台東縣・卑南族              # 產 prompt，服裝規範由 costume.json 灌
python3 tools/build_prompt.py 台東縣・卑南族 --checklist   # 出圖後照這份逐項驗收
```

特別版等於對外宣稱，門檻比普通版高：`scene.costume_basis` 必須寫明每一項對回
`costume.json` 的哪一欄，該族在資料集裡沒有逐部位資料（例如馬卡道族、馬祖）就直接擋下來。

新竹縣與新竹市、嘉義市與嘉義縣共用同一張原始海報，但 `id` 必須各自獨立，
否則批次生圖時後者會被當成「已存在」而跳過。

地圖路徑（`const MAP`）由 [g0v/twgeojson](https://github.com/g0v/twgeojson) 的
`twCounty2010.geo.json` 轉出，除非要換底圖否則不用動。

## 產線

底圖採**拆分重組**：畫面裡沒有任何文字，上緣 22% 與右緣 40% 刻意留空，
文字全部由 HTML 疊上去。所以改字不必重生圖。

```bash
python3 tools/build_prompt.py 高雄市      # 由資料產生 prompt，不要手打
bash tools/gen_all.sh                     # 批次生所有缺底圖的縣市
bash tools/gen_all.sh 澎湖縣 金門縣        # 只生指定的
python3 tools/verify_base.py              # 量測版面是否合規
python3 tools/register_base.py            # 驗收過後把 base 欄位寫回資料
python3 tools/sync_split.py               # 資料同步進 index.html
```

新住民數字每月更新，跟生圖是兩條線：

```bash
python3 tools/fetch_immigration_stats.py  # 抓最新一期，存原文＋產 newcomers.json
python3 tools/sync_split.py               # 數字才會進 index.html
```

`verify_base.py` 量四件事：文字區的亮度與局部起伏（太暗或太雜，疊上去的字就讀不到）、
以及**右側 40% 的結構下限**（太空，畫面會空洞）。下限是後來才補的——原本只有上限，
所以四張右側是大片空霧的圖一直沒被抓出來。
量測區的座標不是猜的，是用瀏覽器量 `.split-top` 與 `.split-side` 的實際位置換算回來的。

**codex 一次會產生多個候選（實測 2–9 張），全部都要看。** 它不是逐步改進，
是產生多個不同的嘗試——最新的那張不代表最好。`gen.sh` 會把全部候選存到
`<輸出檔>.cand/`，用審查頁挑：

```bash
python3 tools/review.py                          # 產生 review/index.html
python3 tools/pick.py 桃園市 04 --note "理由"     # 換上並自動量測、同步、重建審查頁
```

83 張候選逐一比對後，16 個縣市的預設選擇被換掉，全部是同一個原因：**右邊有東西的比較好看**。
美術指導的六條與量測門檻的演變寫在 [AGENTS.md](AGENTS.md)。

## 背景音樂與海面互動

第一次互動後自動播放，導覽列右上角的按鈕可以關；關過的人不再自動開。
音檔 2.9MB，**按下去才載**，不聽的人完全不付這個成本。

海面有四層會跟著音樂起伏，刻意分吃不同頻段，否則會一起漲落像機械連桿：

| 層 | 驅動 |
|---|---|
| 三層色塊浪 | 低頻。用 `scale` 讓浪峰變形而不是整塊平移——216px 高的色塊平移 4px 是看不出來的 |
| 泡沫水線 | 低頻。貼在水線上的泡沫絮團跟著一起涌 |
| 兩線之間的泡沫帶 | 位置在兩條線之間內插 |
| 音浪線 | 中高頻。與上面那條反向漂流，會互相穿插交錯 |

音量走自動增益：追蹤各頻段自己的動態範圍，換一首曲子也不會卡在頂端或整個不動。

## 分享預覽與 SEO

`img/og.jpg`（1200×630）是分享到 Facebook、LINE、Threads 時的預覽圖。
這種視覺型專案沒有 `og:image`，分享出去就只有一行字。

`index.html` 的 `<head>` 裡有 Open Graph 與 Twitter Card 標籤，
外加 `robots.txt` 與 `sitemap.xml`。

**網址是寫死的**（目前指向 `https://yazelin.github.io/taiwan-people/`）。
換網域的話 `canonical`、`og:url`、`og:image`、`robots.txt`、`sitemap.xml`
五個地方都要一起改，漏掉任何一個，預覽圖就會指到不存在的位置。

## 已知的資料問題

原始海報由 AI 生成，底部那排代表物**有錯**，不要直接抄進網頁：

- 高雄那張的「代表樹 鳳凰木」「代表鳥 黑面琵鷺」其實是**台南**的市樹與市鳥
- 「代表海產 石敢・櫻搏」不是詞
- 雲林那張寫代表花是劍蘭、彰化寫文心蘭、南投寫台灣櫻花、金門寫「石蚵花」，
  都跟查證資料不符

所以所有文字以 `data/counties.json` 為準，該檔每筆象徵都帶 `source`。

**目前的查證狀態**：市花已逐一到各縣市政府網站核對。
**11 個縣市有公開的象徵頁面，全部與原資料吻合、零衝突**（基隆、台北、新北、新竹縣、台中、彰化、南投、嘉義市、台南、高雄、澎湖），
順帶也確認了其中幾個縣市的市樹與市鳥。

其餘 11 個縣市（桃園市、新竹市、宜蘭縣、苗栗縣、雲林縣、嘉義縣、屏東縣、花蓮縣、台東縣、金門縣、連江縣）**官網沒有公開的象徵頁面**——
首頁無連結、站內搜尋查無、搜尋引擎也只找到不相關的頁面，有幾個站還擋自動抓取。
那是查證結果本身，不是查證疏漏；要再往下只剩打電話問民政處或翻縣志與地方法規。
這批資料原本來自維基的「台灣各縣市象徵列表」，11 個獨立來源全部吻合，
代表該表品質可信，但未經核對的那幾筆仍不算一手來源。

**還沒查證的兩筆配件依據**：基隆水手帽←基隆港、苗栗藍花頭巾←客家，
資料的 `accessory_basis` 有標記。

**新竹縣與嘉義縣的造型是推定的**——那兩個縣市沒有自己的海報。

**原住民族織紋**（花蓮、台東、屏東、南投）依原海報保留視覺但不指名族群：
光台東就有阿美、卑南、排灣、布農、達悟五族，指錯族群的織紋比指錯市樹嚴重。
正式對外發佈前建議先請具代表性的族人或相關單位過目。

這一條現在有了對策：`data/costume.json` 與 [`costume.html`](costume.html) 整理了
16 族原住民族、4 個平埔族群、客家與閩南／閩東共 23 個族群的服飾資料，
每一筆都對得回官方機關、公立博物館或政府委託之學術調查的原始出處，
並附群別差異、階級規範與出圖驗收清單。**下一輪重畫任何一個縣市之前，先讀那個檔案。**
不過資料集本身還沒有經過各族群代表或相關單位審閱，這一點沒有改變。

**服裝欄已依此修過，五張底圖因此與資料不符、需要重生**（各筆的 `todo` 有標記）：

| 縣市 | 原本 | 現在 |
|---|---|---|
| 花蓮、台東、屏東、南投 | 幾何織紋滾邊＋多層串珠，對不回任何一族 | 當代穿著。傳統服飾交給特別版 |
| 新竹縣、苗栗 | 「客家藍衫（立領盤扣、白色小花印花）」 | 普通版改當代穿著；北客大襟衫依客委會調查改對後，移到 `新竹縣・客家`、`苗栗縣・客家` 兩個特別版 |

那三處錯誤分別是：印花把 1960 年代的花布誤當客家傳統、盤扣是對襟的做法（大襟衫用直布扣）、
藍衫是南部六堆的稱法（桃竹苗屬北客）。苗栗那條「藍花頭巾←客家」查不到官方依據，已刪。
`build_prompt.py` 現在會擋掉「有族群織紋但沒有依據」的資料——苗栗就是被它抓出來的。

## 另外三張的問題：右側太空，以及一個地理錯誤

補上「右側結構下限」的量測之後，抓出四張右側是大片空霧的（台北、新北、彰化、南投）。
查根因發現有一半不是模型畫不好，是 `right_zone` 跟 `viewpoint` 互相矛盾：
彰化的視點在鹿港老街巷弄裡，卻要求右側畫海。

**順帶目視抓到一張量測抓不到的**：新竹市的視點在城隍廟前廣場，
現用底圖右側卻畫著海與港灣拱橋——市中心的廟埕看不到海。
它的量測分數是通過的（右側有內容），因為量測永遠不會問「這個場景成立嗎」。

三張的 `right_zone` 已改對並補上逐縣市的 `right_zone_desc`，等待重生。

這組資料的鑑別度也沒有想像中高：樟樹同時是苗栗、南投、雲林、台東的縣樹，
蝴蝶蘭同時是雲林、台南、台東的縣花，台灣藍鵲同時是台北、桃園、雲林的市鳥。
南投縣、嘉義市、金門縣則沒有指定縣鳥。
