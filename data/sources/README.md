會把政府網站的內容抄一份進 repo，是因為連結會爛。這幾年已經看過官方頁面改版之後
整段消失、或是網址換掉但沒有轉址的情況。只留網址，等於幾年後沒有人能驗證我寫的是不是真的。
留下當時抓到的原文，別人可以自己比對。

**沒有收進來的**：客委會那份調查報告的 PDF 全文（7.5MB，含 200 件文物的逐件記錄表與照片）。
檔案太大不適合進版控，網址在 `costume.json` 的 `sources.hakka-survey`。

存檔由 `tools/archive_sources.py` 產生，可以重複跑：只補還沒存的，`--force` 才全部重抓。

**抓不到就明講。** 空殼存下來比沒存更糟——看起來有存檔，實際上驗證不了任何東西。
所以低於 400 字的一律拒絕寫檔並列出來，由人另外處理。目前 70 筆來源全部存檔完成，
一筆都沒有列在裡面。

抓不到通常是三種原因，處理方式不同：

1. **純前端渲染**：HTML 原始碼裡沒有內容，要用瀏覽器存渲染後的結果。
2. **網址已死但會轉址到首頁**：`curl` 拿到 **200**，內容早就不在了。只檢查狀態碼會以為它還活著。
3. **那根本是查詢介面而不是文件**：那就不該放在 `sources`，應該放在 `costume.json` 的 `collections`。

第二種真的踩到了。連江縣政府原本引用的 `/chhtml/newslist/371040100A/2121` 會轉址到縣府首頁，
`curl` 回 200。一開始判斷成第一種（前端渲染），但**用 Chrome 開也一樣落在首頁**——
所以不是渲染問題，是那個位址上的內容已經沒了。該來源已改為文化部典藏網的馬祖民俗文物館分館，
那裡是活的，而且搜「服」有三十五筆帶色卡的實物棚拍。

教訓是：「HTTP 抓不到」與「瀏覽器也拿不到」是兩件事，不要用前者推論後者。

抓取日期：2026 年 8 月。抓取方式是直接讀網頁 HTML 再去標籤，沒有經過任何模型改寫，
所以文字與當時的原始頁面一致。

`immigration/` 這一份是例外：來源本身就是試算表，抓法是直接讀 ODS 轉成 TSV，
一格對一格，沒有挑欄位也沒有算過。它由 `tools/fetch_immigration_stats.py` 產生，
每跑一次多一份，舊的留著——數字會變，留下每一期才看得出變在哪裡。
